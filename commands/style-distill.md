# 文风蒸馏器

用户触发了文风蒸馏流程。目标是分析一位作者的写作样本，提取风格特征，生成一份「风格档案」保存到 `styles/` 目录，供 `/zhihu-story` 在生成故事时引用。

## Step 1 — 收集输入

用 AskUserQuestion 一次性问用户以下问题：

1. **文本来源**：
   - 选项A：直接贴文本到对话里
   - 选项B：提供文件路径（支持 .txt / .md / .docx）
   - 提示用户：样本越多越好，建议至少3000字，最好1万字以上

2. **风格命名**：用于命名档案文件（如「匪我思存」「priest」「某某风格」）

3. **要提取的维度**（用户自己指定，给出以下作为参考）：
   - 句式节奏（句子长度分布、断句习惯、长短句交错模式）
   - 用词偏好（高频词、特色用词、口头禅、词汇层级）
   - 比喻风格（比喻来源域、精准度、频率、是否追求文学性）
   - 叙事手法（视角切换、时间处理、信息揭示方式、悬念节奏）
   - 对话风格（对话长度、标签使用、潜台词处理、角色区分度）
   - 情绪处理（show/tell比例、情绪表达偏好、内心活动写法）
   - 段落结构（段落长度分布、场景切换方式、独句段使用频率）
   - 开头/结尾模式（偏好什么方式开场和收束）
   - 环境描写（频率、长度、感官偏好、与情节的关系）
   - 其他（用户自定义维度）

如果用户已在触发消息中提供了部分信息（如文件路径或维度），跳过对应问题。

## Step 2 — 读取并分析文本

### 2.1 读取文本

如果是文件路径，用 Read 工具读取。如果文件较大（超过2000行），分段读取。

### 2.2 逐维度分析

对用户指定的每个维度，进行以下分析：

**分析方法**：
- 统计性分析：句子长度分布、段落长度分布、对话占比、特定词频等
- 模式识别：找出反复出现的写作模式（如开头习惯、过渡方式、情绪处理方式）
- 对比提取：与「一般AI写法」或「网文通用写法」对比，找出该作者的独特之处

**每个维度的输出格式**：

```markdown
### 维度名

**一句话概括**：该作者在这个维度最显著的特征

**具体规则**（生成时可直接执行的指令）：
1. 规则1
   > 原文例句："..."
2. 规则2
   > 原文例句："..."
3. 规则3
   > 原文例句："..."

**对比**：
| 一般写法 | 该作者写法 |
|---|---|
| ... | ...（引用原文）|

**量化指标**（如适用）：
- 平均句长：X字
- 段落平均句数：X句
- 对话占比：约X%
- ...
```

### 2.3 提取「签名手法」

在所有维度分析完成后，额外提取 2-3 个该作者最有辨识度的「签名手法」——那种读到就知道是这个作者的东西。

## Step 3 — 生成风格档案

将分析结果整合为一个 markdown 文件，格式如下：

```markdown
---
name: 作者名
source: "分析样本来源描述（如：《XX》前3万字）"
dimensions: ["维度1", "维度2", ...]
created: YYYY-MM-DD
---

# 作者名 — 文风档案

## 一句话风格概括
...

## 签名手法
1. **手法名**：描述 + 原文例句
2. **手法名**：描述 + 原文例句
3. **手法名**：描述 + 原文例句

## 维度1：句式节奏
（分析内容，格式同上）

## 维度2：用词偏好
（分析内容）

...

## 使用注意

### 优先级
- **anti-detection.md 的所有规则仍然生效且优先级最高**。本档案的风格规则不得覆盖反检测规则（段落长度波动、废话注入、直接讲述比例、结尾动作收束等）。
- 本档案替代 writing-style.md 中的通用风格规则（句式节奏、用词偏好、比喻风格等维度以本档案为准）。
- writing-style.md 中的基础规则（反翻译腔、AI高频词替代池）仍然生效。

### 风格 vs 反检测的平衡
如果该作者的某个风格特征恰好是AI检测器的敏感模式（如：该作者确实喜欢用排比、确实喜欢比喻回调），在「使用注意」中标注，生成时适度使用但不要过度。
```

## Step 4 — 保存并确认

保存档案到：
```
/home/liuy405/.claude/plugins/local/zhihu-story-generator/styles/作者名.md
```

文件名用作者名/风格名，去掉空格和特殊字符。

保存后告诉用户：
- 档案已保存到哪个路径
- 包含了哪些维度
- 在 `/zhihu-story` 中如何使用（Phase 1 选类型时会看到该风格选项）

## 重要原则

- 分析要基于原文，不要脑补。每条规则都必须有原文例句支撑
- 不要把所有作者都分析成同一种风格——找的是**差异**，不是共性
- 签名手法要足够具体，具体到「这个手法换一个作者就不会这么写」的程度
- 风格档案不是文学评论，是**可执行的写作指令**——生成时能直接照着做的那种

用户的额外参数：$ARGUMENTS
