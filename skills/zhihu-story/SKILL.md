# 知乎盐选故事生成器

## 工作流总览

整个流程分6个阶段，中间只在"用户选概念"时暂停，其余一气呵成。

Phase 1 需求确认 → Phase 2 概念头脑风暴 → Phase 3 全文生成 → **Phase 3.5 反检测改写** → **Phase 3.8 质量自检** → Phase 4 发布素材+导出

---

## Phase 1 — 需求确认

读取 `references/genre-guides.md` 了解可用类型。
检查 `styles/` 目录下是否有已保存的风格档案（用 Bash 列出 `styles/*.md`，排除 .gitkeep）。

用 AskUserQuestion 一次性问用户以下问题（合并为1-2个问题，不要逐个问）：

1. **类型**：古言 / 现代言情 / 悬疑 / 脑洞 / 爽文（单选）
2. **子类型**：根据所选类型给出选项（如古言下有：甜宠、追妻火葬场、权谋、穿书/重生、种田经商）
3. **结局**：HE（甜）/ BE（虐）/ OE（开放）
4. **目标字数**：默认1万字，用户可指定（如1.5万、2万、3万）。最低不少于1万字
5. **风格模板**（可选）：是否模拟某位作者的文风？如果 `styles/` 目录下有已保存的档案，列出供选择；也可选「默认风格（不使用）」。如果没有任何档案，提示用户可以用 `/style-distill` 先蒸馏一个

如果用户已在触发消息中说明了类型（如"写个古言甜宠"），跳过对应问题，直接进入 Phase 2。

可选：问用户是否有故事种子或灵感片段。没有就由 AI 自由发挥。

---

## Phase 2 — 概念头脑风暴

读取 `references/zhihu-editorial.md` 获取选题标准和编辑审稿维度。

根据用户选择的类型+子类型，生成 **5个完全不同的故事概念**。每个概念包含：

```
## 概念N：概念名（2-4字）
**一句话卖点**：一句能让人想点进去的话（知乎标题风格）
**设定**：3句话描述核心设定和开篇场景
**核心反转**：故事最大的转折点
**导语草稿**：150-220字，一句一段，包含核心冲突+人物底色+情绪钩子+信息缺口
**付费墙断点**：3000-4000字处的悬念/反转设计（身份揭露、致命反转、情感炸弹）
```

5个概念要在以下维度上拉开差异：
- 时代背景不同（如：架空 vs 历史朝代 vs 古风仙侠）
- 女主人设不同（如：替嫁庶女 vs 穿书大佬 vs 落魄公主）
- 冲突类型不同（如：身份隐瞒 vs 复仇 vs 宿命对立）
- 甜的方式不同（如：反差萌 vs 暗恋成真 vs 先婚后爱 vs 欢喜冤家）

输出5个概念后，让用户选择（直接说数字即可）。

## Phase 3 — 全文生成

这是核心阶段。读取以下参考文件：
- `references/anti-detection.md` — **反 AI 检测策略（最高优先级，不可覆盖）**
- 如果用户在 Phase 1 选了风格档案：读取 `styles/作者名.md` — **风格档案（替代 writing-style.md 的对应维度）**
- `references/writing-style.md` — 写作风格和去AI味规则（如有风格档案，档案中覆盖的维度以档案为准，未覆盖的维度仍用此文件）
- `references/zhihu-editorial.md` — 结构要求和节奏控制
- `references/genre-guides.md` — 对应类型的专属规则
- `references/zhihu-baokuan-style.md` — 爆款风格模式（导语、段落、钩子、付费墙）

**优先级**：`anti-detection.md > 风格档案 > writing-style.md > 其他参考文件`

### 写作规则

**反检测（最高优先级，贯穿全文，覆盖其他规则）**：
- 生成前必须读取 `references/anti-detection.md` 并严格执行，**当 anti-detection.md 的要求与其他文件冲突时，以 anti-detection.md 为准**
- **写作时执行以下硬指标**（不是建议，是必须达到的数量）：
  - 每千字包含 2-3 个 4句以上的长段落（不是恰好2个——数量本身也要有波动）
  - 每2000字包含 3-4 句直接讲述情绪的句子（"我有点慌""说不上来什么感觉"），不低于这个密度
  - 每2000字包含 2-3 句与情节无关的废话/跑题/吐槽（嵌入到正常段落中，不要独立成段）
  - 全文「独句成段式过渡」（"不对。""算了。"这种戏剧性独句转折）不超过 3 次。注意：对话独句段和这个不同，对话独句段不受此限制
  - 全文双重强调（两句话换措辞说同一件事）不超过 1 次
  - 结尾最后一句必须是具体身体动作（不是感悟、不是比喻回调、不是动物拟人）
  - 看点密度全文平均每600-800字一个，但不要均匀分布——有的段落1000字没有看点（日常铺垫），有的段落300字内连续两个看点
- 这些是硬性要求。生成完毕后在 Phase 3.5 中逐项核实，不达标就改到达标

**叙事**：
- 必须使用第一人称"我"叙事
- 内心活动直接写成叙述，不用"我心想""我暗道"

**结构**：
- 篇幅按用户指定的目标字数生成，默认不少于1万字。如果用户要求更长（如2万、3万字），增加情节线、副线和场景数量来填充，不要注水
- 用数字标号（1. 2. 3. ...）分隔场景段落
- 正文前放导语（一句一段，150-220字，包含冲突+人物+悬念）
- 开篇 150-350 字内：抛出最抓人的悬念或冲突（不必精确卡在200字）
- 前 800-1200 字：让读者明确主角欲望+动机（位置可以灵活）
- 前 1/4 到 2/5 之间的某个自然位置：设置转折或小高潮
- 前 3000-4000 字：付费墙断点，必须是强悬念或反转（身份揭露、致命反转、情感炸弹），让读者不可能不付费
- 全文后半段的某个出人意料的位置：放最大反转（不必精确在 2/3 处）
- 结尾：收束干净，有余韵，HE/BE/OE按用户选择
- **节奏不要机械化**：不是每个场景都遵循「悬念-发展-高潮」模式，有些场景就是日常，有些场景突然开始突然结束

**人物**：
- 总人物 3-5 人，开篇不超过 3 人
- **性格标签前置**：每个主要角色先确定2-3个性格标签（如：记仇+嘴硬+护短），再写对话。性格决定说话方式，不是反过来
- **对话区分度**（遮名测试）：遮掉角色名后，仅凭说话方式就能分辨谁在说话。做法：给每个角色分配1-2个语言标签（如：角色A说话带"嗯"的尾音、角色B喜欢反问、角色C说话很短很直），对话中严格执行
- 配角要有记忆点（外貌特征或行为习惯）
- **至少1个角色做出「不太合理但很真实」的行为**：人在真实情境中会做非理性的事——明知道不该回头却回头了、该生气的时候反而笑了、有机会报仇却放弃了。AI的角色行为过于「合理」，每个决策都有清晰的因果链。让至少1个角色做一次「说不清为什么但就是这么做了」的事

**文笔**（参考 writing-style.md 中的替代池和对比示范）：
- 动词优先，形容词是最后手段——但偶尔一个好的形容词也有力量
- 一句话只做一件事，超过25字考虑拆开——但偶尔一个30-40字的长句能制造呼吸感
- 大部分时候用具体动作/身体反应代替情绪标签（Show don't tell），但偶尔直接讲述也行
- 环境描写最多1-2句，服务于情绪。**描写必须通过角色的身体感受**，不是拍纪录片——「右脸被火烤得发烫」比「火焰熊熊燃烧」有效一万倍。读者要跟着角色跑，不是站在旁边看
- 对话短促有力，多数时候用动作代替"说"字，但偶尔直接用「说」也正常
- 多数段落结尾有钩子，但不是每段都硬装——偶尔松一口气
- **禁止水文**：每句话必须提供新信息（新的画面/动作/情绪/信息）。如果一句话删掉后不影响任何东西，这句话就是水文，删掉。不要用不同的句式把同一个意思再说一遍——「宛如被抛弃的婴儿般掉落在街上」这种强行比喻不提供任何新信息，只会让读者出戏
- 参考 AI 高频词替代池（writing-style.md），避免高频使用以下词汇，但**不是绝对禁用**——偶尔用一次「似乎」「仿佛」是正常的，关键是不要每段都用。每种 AI 词汇的替代方式要在文中混合使用，不要形成新的固定模式

**反翻译腔**（参考 writing-style.md 第七章，极重要）：
- 名词前修饰语不超过6个字。先写名词，再用独立短句描写属性
- 一个分句不超过2个"的"，严禁"长修饰语+的+名词"结构
- 描写环境/物品时结合动作交互和感官体验，不要罗列静态属性
- 错误：`那扇锈迹斑斑且散发着恶臭的铁门` → 正确：`那扇铁门，锈迹斑斑，散发着一股恶臭`

**节奏**：
- 全文平均每600-800字一个看点（悬念/冲突/反转/信息揭示/情感爆发），但不要均匀——有的段落1000字铺日常，有的段落300字内连续两个看点
- 紧张处用极短句连击，舒缓处用长句或长段落铺开
- 对话占比全文平均 30-50%，**各场景之间波动要大**（有的场景80%对话，有的场景纯叙述0%对话）
- 纯叙述段不超过连续 400 字
- 段落长度要有剧烈波动：短段落1-2句，中段落3-4句，长段落5-8句，**偶尔出现1个8-10句的超长段落**（用于内心挣扎/回忆/环境铺设）
- **每个场景至少1次非视觉感官描写**：气味、声音、触感、温度、味道。AI的描写以视觉为主，缺少其他感官是显著的AI特征

### 输出格式

直接输出完整故事正文。用数字标号分段，不要章节标题。

## Phase 3.5 — 强制改写（不是检查，是必须执行的改写）

全文生成后，**必须执行以下全部改写操作**。这不是「检查有没有问题」——这是「不管有没有问题都必须做的修改」。跳过任何一项都会导致被AI检测器识别。

### 必须执行的 7 项改写（每一项都要实际动手改文本）

**① 合并3组短段落 → 长段落**
在全文中找到3个地方，把2-3个相邻的短段落合并成1个4-6句的长段落。合并后的长段落不需要每句都推进情节，可以包含感官描写、内心闲聊、环境细节。

**② 插入3句直接讲述**
找到3个用动作展示情绪的地方（如"她攥紧了袖口"），把其中3处改成直接讲述。用口语化的方式：「说实话我有点慌」「心里乱得很」「我也不知道自己在紧张什么」。不要文艺，像跟朋友聊天。

**③ 插入3句废话/跑题**
在全文中插入恰好3句跟情节无关的内容。类型：
- 叙述者吐槽（"运气差成这样也是一种天赋"）
- 无关联想（"这味道跟我姥姥家的中药铺子一模一样"）
- 无关细节（"墙角有只壁虎，一动不动盯着蜡烛"）

**④ 重写结尾最后200字**
这是被检测概率最高的部分。结尾必须满足以下全部条件：
- 最后一句必须是一个**具体的身体动作**（走路、关门、喝水、翻身），不是感悟/比喻/回调
- 禁止在最后200字内出现：感官排比（列举多种味道/声音）、比喻回调（首尾呼应的文字游戏）、动物或配角的拟人化点评（"好像在说，终于"）
- 禁止「X。Y+X，Y。」的双重强调句式（如"没人管。三畦金线莲，没人管。"）

**⑤ 消灭双重强调**
全文搜索是否有「用两句不同措辞说同一件事」的地方，找到了就删掉一句，只保留一句+角色反应。

**⑥ 打散1处信息堆**
找到1处连续3个以上短段落在逐步揭示信息的地方，把它们合并成1个密集的长段落（一口气说完）。

**⑦ 确认结尾动作收束**
最后再检查一次结尾最后一句——如果不是具体身体动作，改成一个。
- ✅ "我把凤冠搁回桌上，翻了个身，闭眼了。"
- ✅ "我端起那杯凉透的茶，一口喝完。"

**⑧ 情节桥段堆叠检查**
检查每个场景里是否堆叠了超过2个「经典桥段」（参见 anti-detection.md 第十二章的清单）。如果一个场景里有3个以上经典桥段（如雨中递外套+闻到味道触发回忆+走马路那侧+步调同步），必须删掉其中1-2个，并插入一个「不浪漫的扫兴细节」（踩水坑、手机响、肚子叫）。

**⑨ 非理性行为检查**
全文是否有至少1个角色做出了「不太合理但很真实」的行为？如果所有角色的每个决策都有清晰的因果逻辑，找一个角色加一个非理性行为——不需要解释为什么，让它悬着。（参见 anti-detection.md 第十二章）

**⑩ 非视觉感官检查**
每个主要场景是否至少有1次非视觉感官描写（气味/声音/触感/温度/味道）？如果全是视觉描写，每个场景补1个其他感官。

**⑪ 风格档案保持（仅在选用了风格档案时执行）**
如果本次生成使用了风格档案，检查①-⑧的改写是否破坏了档案中的「签名手法」。如果某个签名手法被改写步骤误伤了（如档案要求的特定句式被合并段落时拆掉了），恢复它。反检测规则仍然优先，但在不违反反检测的前提下尽量保持风格特征。

改写完毕后进入 Phase 3.8。

## Phase 3.8 — 质量自检

读取 `references/quality-checklist.md`，对全文执行以下快速检查（不需要逐字扫描，重点检查高风险项）：

1. **伏笔回收**：全文埋的伏笔是否全部回收？有没有「提了但没收」的悬案？
2. **时间线**：人物年龄和事件间隔是否自洽？如果涉及「X年前」「等了X年」这类表述，交叉验证数字
3. **逻辑红线**：每个重要转折前是否有铺垫？角色动机是否被看见？有没有凭空出现的巧合？
4. **主角底线**：主角是否有明确不可退让的东西？是否有爆发点？
5. **获得感**：读者读完后心里能「多点什么」吗？至少满足：1处情感共鸣 + 1处情绪释放 + 3句可截图金句（三种中满足两种即可）
6. **内部查重**：同类场景有没有重复出现但没有新信息？同一情绪有没有原地打转没有递进？
7. **细节创新**：全文是否有至少1处「读者没见过的具体动作或细节」——在大家以为「到这里就该这样了」的位置，做了一个意外的事？

如果发现问题，直接修改。修改完毕后输出最终版本，不要展示修改过程。

## Phase 4 — 发布素材 + 导出

故事生成完毕后，立即生成发布素材并与正文合并保存。

### 发布素材格式

```markdown
# 发布素材

## 导语

150-220字，一句一段，放在正文最前面。包含：核心冲突暗示 + 人物底色展示 + 情绪钩子 + 信息缺口。结尾必须有未解决的悬念。

## 书名建议
每个书名严格控制在15字以内（含标点），超过15字必须缩短。
1. **书名1** — 为什么好
2. **书名2** — 为什么好
3. **书名3** — 为什么好

## 主角人设
- 女主：姓名 — 人设标签
- 男主：姓名 — 人设标签
- CP线：一句话对比句

## 标签
标签1、标签2、...（8-10个）

## 金句 / Hook
1. "金句1" — 适用场景
2. "金句2" — 适用场景
3. "金句3" — 适用场景

## 一句话简介
50字以内

## 作品简介（100字）
...

## 详细简介（300字）
...
```

### 保存文件

将「发布素材 + 正文」合并为一个 markdown 文件，保存到用户桌面。
文件名用书名建议的第一个（已限制15字以内，可直接作文件名）。路径：

- Windows (WSL): `/mnt/c/Users/*/Desktop/`
- macOS: `~/Desktop/`

保存前问用户确认文件名和路径。

## 重要原则

- 不要在生成过程中解释你在做什么，直接输出内容
- 概念头脑风暴时输出要紧凑，不要写太多解释
- 全文生成时不要分段输出让用户确认，一气呵成
- 生成的故事是独立的完整作品，不依赖任何外部系统
