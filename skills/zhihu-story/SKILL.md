# 知乎盐选故事生成器

## 工作流总览

整个流程分7个阶段，中间只在"用户选概念"时暂停，其余一气呵成。

Phase 1 需求确认 → Phase 2 概念头脑风暴 → **Phase 2.5 细纲设计** → Phase 3 全文生成 → **Phase 3.5 反检测改写** → **Phase 3.8 质量自检** → Phase 4 发布素材+导出

---

## Phase 1 — 需求确认

读取 `references/genre-guides.md` 了解可用类型。
检查 `styles/` 目录下是否有已保存的风格档案（用 Bash 列出 `styles/*.md`，排除 .gitkeep）。

用 AskUserQuestion 一次性问用户以下问题（合并为1-2个问题，不要逐个问）：

1. **类型**：古言 / 现代言情 / 悬疑 / 脑洞 / 爽文（单选）
2. **子类型**：根据所选类型给出选项（如古言下有：甜宠、追妻火葬场、权谋、穿书/重生、种田经商）
3. **结局**：HE（甜）/ BE（虐）/ OE（开放）
4. **目标字数**：默认1万字，用户可指定（如1.5万、2万、3万）。最低不少于1万字
5. **风格模板**（可选）：是否模拟某位作者的文风？如果 `styles/` 目录下有已保存的档案，列出供选择；也可选「不使用」。如果没有任何档案，提示用户可以用 `/style-distill` 先蒸馏一个
6. **文风预设**（如果未选风格模板则必选）：读取 `references/voice-presets.md`，列出可选文风：
   - 古言清冷型（薄情自知风）— 情绪压在水下，越疼越轻描淡写
   - 口语松弛型（老莫风）— 像朋友在聊天，有吐槽有烟火气【默认】
   - 民间说书人型（话本腔）— 有人在对面给你讲故事
   - 毒舌吐槽型（辛辣风）— 嘴毒心热，每段一个金句
   - 沙雕轻喜剧型（脑洞抽疯风）— 荒诞但自洽，笑点密集
   
   如果用户已选了风格模板，文风预设不生效（风格模板优先级更高）。

如果用户已在触发消息中说明了类型（如"写个古言甜宠"），跳过对应问题，直接进入 Phase 2。

可选：问用户是否有故事种子或灵感片段。没有就由 AI 自由发挥。

## Phase 2 — 概念头脑风暴

读取 `references/zhihu-editorial.md` 获取选题标准和编辑审稿维度。

根据用户选择的类型+子类型，生成 **5个完全不同的故事概念**。每个概念包含：

```
## 概念N：概念名（2-4字）
**一句话卖点**：一句能让人想点进去的话（知乎标题风格）
**设定**：3句话描述核心设定和开篇场景
**核心反转**：故事最大的转折点（必须通过"反转独特性检验"——见下方）
**这个故事的"没见过"**：1句话说明这个概念中，哪个元素是编辑/读者在同类故事中没见过的
**导语草稿**：150-220字，一句一段，包含核心冲突+人物底色+情绪钩子+信息缺口
**付费墙断点**：3000-4000字处的悬念/反转设计（身份揭露、致命反转、情感炸弹）
```

### 反套路概念生成规则（极重要——编辑拒稿理由第一条就是"套路化"）

**高频套路回避清单**——以下模式编辑每天审几十篇，再好的文笔也救不了套路化的骨架：
- ❌ 穿书/重生后靠"先知"逆转命运（太多了）→ 改成：先知信息是错的/不完整的，主角根据错误信息做了更糟的决策
- ❌ 替嫁后被冷面王爷/将军日久生情（标准流水线）→ 改成：替嫁是主角主动策划的，她有自己的目的
- ❌ 白月光vs替身的三角关系（已被写烂）→ 改成：白月光根本不存在/白月光是主角自己/白月光和替身是同一阵营
- ❌ 误会→虐→解除误会→HE 的固定弧线 → 改成：误会被快速解除但解除后产生了更大的问题
- ❌ 身世揭秘作为唯一反转（悬念单薄）→ 改成：身世揭秘在中段就完成，真正的反转是身世揭秘后角色的选择
- ❌ "所有人都以为她是废物其实她是大佬"的装弱打脸循环 → 改成：她确实某方面不行，但用另一个完全出乎意料的能力解决了问题

**概念独特性自检**——每个概念生成后问自己：
1. 如果我把这个故事的设定告诉一个每天审稿的知乎编辑，她会说"又来了"还是"这个有意思"？
2. 核心反转能不能用一句话概括为某个已知套路？如果能，这个反转就不够独特
3. 主角的核心困境，是外部强加的（被替嫁/被陷害）还是她自己选择走进去的？后者更有张力

5个概念要在以下维度上拉开差异：
- 时代背景不同（如：架空 vs 历史朝代 vs 古风仙侠）
- 女主人设不同（如：替嫁庶女 vs 穿书大佬 vs 落魄公主）
- 冲突类型不同（如：身份隐瞒 vs 复仇 vs 宿命对立）
- 甜的方式不同（如：反差萌 vs 暗恋成真 vs 先婚后爱 vs 欢喜冤家）
- **至少2个概念必须包含一个"反常识设定"**——角色关系、世界规则或故事前提中有一个违反读者直觉的元素

输出5个概念后，让用户选择（直接说数字即可）。

### 用户选定概念后 — 剧情点大纲

用户选定概念后，**必须先列出完整的剧情点清单**，再进入 Phase 3 写正文。不要跳过这一步。

剧情点密度要求（硬指标）：
- **万字文：≥12个剧情点**（这是下限，不是目标。实际建议15-18个）
- 1.5万字：≥18个
- 2万字：≥24个
- 3万字：≥36个
- 换算公式：**每万字不少于12个剧情点，建议15-18个**

剧情点清单格式：
```
1、事件名（3-8字概括）
2、事件名
3、事件名
...
```

每个剧情点是一个**独立的情节单元**——有自己的小冲突或信息揭示，删掉它故事会断。如果一个"剧情点"删掉后故事完全不受影响，它就不是剧情点，是注水。

### 张力递进检查（必须执行——"情节张力不足"是最常见的拒稿理由）

列完剧情点后，执行以下三项检查，不通过就改大纲：

**① 赌注升级检查**：从第1个剧情点到最后一个，赌注必须总体上升。用一句话标注每个剧情点的赌注是什么：
- 前1/3的赌注：面子/小利益/日常冲突
- 中1/3的赌注：重要关系/安全/核心目标受威胁
- 后1/3的赌注：生死/不可逆的人生选择/所爱之人的命运

如果后面的赌注不比前面大，调换顺序或替换剧情点。

**② 冲突模式唯一性检查**：逐个检查相邻的3-4个剧情点，它们的冲突模式是否重复？
- ❌ "被欺负→反击" "被陷害→自证清白" "被误解→澄清" ——这三个本质上是同一模式（被动受害→主动回应），编辑会判定为"换皮重复"
- ✅ "被欺负→忍了（埋线）" "主动设局→局被人破" "盟友背叛→被迫独立做选择" ——三个冲突的结构完全不同

**③ "删掉测试"**：对每个剧情点问——如果删掉这个点，后面的故事还能成立吗？如果能，这个点是注水，删掉或替换成一个能改变后续走向的事件。

注意事项：
- 有的剧情点能写800字，有的只能写200字，这是正常的。不要为了凑字数把200字的剧情点硬拉到800字
- 如果剧情点不够12个，说明故事容量不够万字，要么加情节线，要么缩减目标字数
- **详略得当**：不要每个剧情点都写一样长。重点情节浓墨重彩（800-1200字），过渡情节一笔带过（200-400字）。为了情绪连贯，有的节里塞两个剧情点，有的节只写一个。但**不要两节写同一个剧情点**——如果一个剧情点跨了两节，说明它太水了，要么压缩要么拆成两个独立的剧情点
- 列完剧情点后**不需要让用户确认**，直接进入 Phase 2.5 细纲设计

## Phase 2.5 — 细纲设计（场景 + 节拍）

细纲是剧情点列表和正文之间的桥梁——把"写什么"变成"怎么展开"。**不做细纲直接写正文 = 没有施工图就盖楼，必然出问题。**

### 为什么需要细纲

| 没有细纲 | 有细纲 |
|---------|-------|
| 写到一半不知道下一段该写什么 | 每段的走向都提前规划好 |
| 场景切换生硬 | 每个场景有明确的进出方式 |
| 对话和叙述比例失衡 | 节拍设计保证动作与反应交替 |
| 场景内冲突原地打转 | 三步递进确保冲突逐级升级 |
| 情绪铺垫不够，高潮无力 | 情绪靶点确保每个场景有明确的读者感受 |

### 第一步：场景拆解

将剧情点列表分组为场景。一个场景 = 同一时间、同一地点的一段连贯叙事。

**场景密度参考**（以1.5万字为例）：
- 全文 10-15 个场景
- 每个场景 800-2000 字
- 开篇（前3000字）：2-3个场景，快速建立情境
- 中段（3000-10000字）：5-8个场景，冲突升级，节奏加快
- 高潮+收束（10000-15000字）：3-4个场景，集中火力

**场景拆解格式**（紧凑输出，不要写太长）：

```
S1 [时间] [地点] [人物] → 核心事件 → 情绪靶点 → ~X字
S2 [时间] [地点] [人物] → 核心事件 → 情绪靶点 → ~X字
...
```

每个场景必须回答：
1. **目标对立**：这个场景里谁想要什么？和谁的目标冲突？（如果场景中所有人目标一致，这个场景没有张力——要么重新设计对立，要么合并到其他场景）
2. **情绪靶点**：读完这个场景，读者应该产生什么情绪？（好奇/心疼/紧张/爽/疼/释然）
3. **进出方式**：怎么进入这个场景？怎么结束？结尾留什么钩子？

### 第二步：关键场景的节拍设计

**不需要为每个场景都写节拍**——只需要为以下场景写节拍：
- 付费墙断点所在的场景
- 全文高潮场景
- 情绪击穿场景（读者最该哭/最该爽的地方）
- 你觉得最难展开的场景

**节拍 = 一个"动作→反应"回合。** 每个关键场景设计 4-7 个节拍。

节拍格式（紧凑输出）：
```
场景SX 节拍：
B1 [谁]做了什么 → [谁]怎么回应 | 功能：建立
B2 [谁]做了什么 → [谁]怎么回应 | 功能：升级
B3 [谁]做了什么 → [谁]怎么回应 | 功能：升级
B4 [谁]做了什么 → [谁]怎么回应 | 功能：转折/揭示
B5 [谁]做了什么 → [谁]怎么回应 | 功能：击穿
B6 [谁]做了什么 → [谁]怎么回应 | 功能：收束+钩子
```

**节拍功能标签**：
- **建立**：确立场景初始状态
- **升级**：冲突强度上一级
- **转折**：改变场景走向
- **揭示**：抛出关键信息
- **击穿**：达到情绪峰值
- **收束**：场景结束，留钩子

### 第三步：场景内冲突三步递进检查

对每个写了节拍的场景，检查冲突是否逐级升级：

| 层级 | 冲突强度 | 表现方式 |
|------|---------|---------|
| 第一层 | 言语试探/轻微对抗 | 平静的对话、暗示、旁敲侧击 |
| 第二层 | 情绪爆发/信息揭示 | 质问、指责、真相公开、情绪失控 |
| 第三层 | 行动升级/不可逆 | 肢体动作、做出选择、一句无法收回的话 |

如果一个场景的节拍从头到尾都在同一个强度上，这个场景就会"闷"——必须有升级。

### 细纲自检清单（快速过一遍）

- [ ] 每个场景有明确的人物目标对立
- [ ] 每个场景的起点≠终点（局面发生了变化）
- [ ] 每个场景有明确的情绪靶点
- [ ] 关键场景的节拍有递进关系
- [ ] 场景之间有过渡（不硬切）
- [ ] 全文场景的情绪靶点不重复（不能连续三个场景都是"心疼"）
- [ ] 付费墙断点所在场景的击穿力度最强

细纲设计完成后，**不需要让用户确认**，直接进入 Phase 3 写正文。

**Phase 3 写正文时，严格按照细纲的场景顺序和节拍展开。** 细纲是施工图，正文是施工过程——施工时可以微调（多写一句少写一句），但不能改图纸（不能跳过场景或改变节拍顺序）。

## Phase 3 — 全文生成

这是核心阶段。**严格按照 Phase 2.5 的细纲展开正文**——细纲是施工图，按场景顺序写，按节拍展开。

**只读取以下2个参考文件**（不要多读，节省 context 给正文输出）：
- `references/anti-detection.md` — **反 AI 检测策略（最高优先级，不可覆盖）**
- `references/writing-style.md` — 写作风格和去AI味规则
- 如果用户在 Phase 1 选了风格档案：额外读取 `styles/作者名.md`（档案中覆盖的维度以档案为准，未覆盖的维度仍用 writing-style.md）

**不要在此阶段读取** zhihu-editorial.md、zhihu-baokuan-style.md、genre-guides.md、quality-checklist.md——它们的核心规则已内嵌在本文件（SKILL.md）的写作规则中，重复读取会撑满 context 导致生成卡住。

**优先级**：`anti-detection.md > 风格档案 > 文风预设(voice-presets.md) > writing-style.md > SKILL.md 内嵌规则`

- 如果用户在 Phase 1 选了**风格档案**：以档案为准，文风预设不生效
- 如果用户选了**文风预设**（如"古言清冷型"）：读取 `references/voice-presets.md` 中对应文风的规则，其中覆盖的维度以文风预设为准，未覆盖的维度仍用 writing-style.md
- 如果两者都未选：使用 writing-style.md 中的默认"老莫"风格

### 细纲执行原则

- **按场景顺序写**：不跳场景，不改顺序
- **按节拍展开**：关键场景的每个节拍都要被正文覆盖到，不能跳过
- **尊重情绪靶点**：每个场景结束时，检查是否命中了设计好的情绪靶点
- **尊重字数分配**：每个场景的实际字数不要偏离预估超过30%
- **允许微调**：写的过程中可以加一两个细节、调整节拍内的对话，但不能改变场景的核心事件和情绪走向

### 写作规则

**反检测（最高优先级，贯穿全文，覆盖其他规则）**：
- 生成前必须读取 `references/anti-detection.md` 并严格执行，**当 anti-detection.md 的要求与其他文件冲突时，以 anti-detection.md 为准**
- **写作时执行以下硬指标**（不是建议，是必须达到的数量）：
  - 每2000字包含 1-2 个 4句以上的长段落（数量本身也要有波动）。**默认段落长度不超过30字**（含对话），长段落是偶尔出现的变奏，不是常态
  - 每2000字包含 3-4 句直接讲述情绪的句子（"我有点慌""说不上来什么感觉"），不低于这个密度
  - 每2000字包含 2-3 句与情节无关的废话/跑题/吐槽（嵌入到正常段落中，不要独立成段）
  - 全文「独句成段式过渡」分类管理（详见 anti-detection.md 第六章）：对话独句段不限制；情绪反应独句段（"不对。""算了。"）不超过3次；**信息揭示独句段（"十七岁。""三天。"）完全禁止**——把信息嵌入上下文句子中
  - 全文双重强调（两句话换措辞说同一件事）不超过 1 次
  - 结尾最后一句必须是具体身体动作（不是感悟、不是比喻回调、不是动物拟人）
  - 看点密度全文平均每600-800字一个，但不要均匀分布——有的段落1000字没有看点（日常铺垫），有的段落300字内连续两个看点
- 这些是硬性要求。生成完毕后在 Phase 3.5 中逐项核实，不达标就改到达标

**防拒稿核心规则（直接对应编辑拒稿理由）**：
- **反套路化**：每个场景必须有自己独特的叙事功能——推动主线、揭示人物新面、改变力量对比、提供关键信息。如果两个场景的功能可以互换，合并或删掉一个
- **张力递进**：全文冲突不能原地打转。如果读者在第5节感受到的紧张感和第3节一样强，说明中间没有升级，必须在第4-5节加入新的赌注
- **文笔流畅**：写的时候像在给朋友讲故事——节奏自然，不端着，不刻意文艺。一句话读出来不拗口是最基本的标准。如果某句话你自己读三遍都觉得别扭，重写它

**叙事**：
- 必须使用第一人称"我"叙事
- 内心活动直接写成叙述，不用"我心想""我暗道"

**结构**：
- 篇幅按用户指定的目标字数生成，默认不少于1万字。如果用户要求更长（如2万、3万字），增加情节线、副线和场景数量来填充，不要注水
- 用数字标号（1. 2. 3. ...）分隔场景段落。**最低分节数量**：万字文≥10节，1.5万字≥14节，2万字≥18节，3万字≥26节。节数不够说明单节太长，读者在手机上看会觉得闷
- 正文前放导语（一句一段，150-220字，包含冲突+人物+悬念）
- 开篇 150-350 字内：抛出最抓人的悬念或冲突（不必精确卡在200字）
- 前 800-1200 字：让读者明确主角欲望+动机（位置可以灵活）
- 前 1/4 到 2/5 之间的某个自然位置：设置转折或小高潮
- 前 3000-4000 字：付费墙断点，必须是强悬念或反转（身份揭露、致命反转、情感炸弹），让读者不可能不付费
- 全文后半段的某个出人意料的位置：放最大反转（不必精确在 2/3 处）
- 结尾：收束干净，有余韵，HE/BE/OE按用户选择
- **顺叙为主**：用顺叙扎扎实实讲一个故事，少用倒叙和插叙。短篇字数有限，倒叙和插叙会打断读者沉浸感、增加阅读门槛。如果非要用倒叙/插叙，全文最多1处，且不超过500字
- **节奏不要机械化**：不是每个场景都遵循「悬念-发展-高潮」模式，有些场景就是日常，有些场景突然开始突然结束

**人物**：
- 总人物 3-5 人，开篇不超过 3 人
- **性格标签前置**：每个主要角色先确定2-3个性格标签（如：记仇+嘴硬+护短），再写对话。性格决定说话方式，不是反过来
- **对话区分度**（遮名测试）：遮掉角色名后，仅凭说话方式就能分辨谁在说话。做法：给每个角色分配1-2个语言标签（如：角色A说话带"嗯"的尾音、角色B喜欢反问、角色C说话很短很直），对话中严格执行
- 配角要有记忆点（外貌特征或行为习惯）
- **至少1个角色做出「不太合理但很真实」的行为**：人在真实情境中会做非理性的事——明知道不该回头却回头了、该生气的时候反而笑了、有机会报仇却放弃了。AI的角色行为过于「合理」，每个决策都有清晰的因果链。让至少1个角色做一次「说不清为什么但就是这么做了」的事
- **重要角色首次出场铺垫**：会影响主线的角色首次出场时，必须有1-2个建立关系感的日常细节——不是"她是我的贴身丫鬟"这种身份交代，而是"她粘我粘得紧，每天都要来我这玩上一会"这种带温度的细节。关系感靠具体细节建立，不靠标签声明

**极简原则（短篇铁律）**：
短篇就那么点篇幅，**每个字都要为剧情推进服务**。除非剧情需要，以下内容能不写就不写：
- **环境描写**：一个短语带过。"桌上放着一盏台灯"，够了。不写它什么颜色什么材质
- **外貌描写**：主要角色用几个字概括即可（"洁白干净""瘦高个"），跑龙套角色可以完全不写。不要写完整的五官描写
- **动作/打斗过程**：如果打斗细节不推动剧情，直接跳到结果。"说实话我也不知道自己是怎么把他打倒的"比写500字的打斗过程更高效
- **穿着描写**：除非穿着本身是剧情线索，否则不写
- **氛围描写**：整篇文最多1-2句氛围描写。不要为了"文学性"写氛围
- **写完任何描写后马上回到剧情**：不要在描写里流连。50字交代完环境，下一句就要推剧情
- **反检测的感官描写怎么办**：anti-detection要求的非视觉感官细节，嵌入剧情推进的句子中，用几个字带过（"药汁苦得我整张脸皱起来"），不要写独立的描写段落。反检测和极简不矛盾——一个感官词嵌在叙述里就够了

**文笔**（参考 writing-style.md 中的替代池和对比示范）：
- 动词优先，形容词是最后手段——但偶尔一个好的形容词也有力量
- 一句话只做一件事，超过25字考虑拆开——但偶尔一个30-40字的长句能制造呼吸感
- 大部分时候用具体动作/身体反应代替情绪标签（Show don't tell），但偶尔直接讲述也行
- 环境描写最多1句，用最少的字交代场景。不要写独立的环境描写段落，把环境信息嵌入角色动作中
- 对话短促有力，多数时候用动作代替"说"字，但偶尔直接用「说」也正常
- 多数段落结尾有钩子，但不是每段都硬装——偶尔松一口气
- **禁止水文**：每句话必须提供新信息（新的画面/动作/情绪/信息）。如果一句话删掉后不影响任何东西，这句话就是水文，删掉。不要用不同的句式把同一个意思再说一遍——「宛如被抛弃的婴儿般掉落在街上」这种强行比喻不提供任何新信息，只会让读者出戏
- 参考 AI 高频词替代池（writing-style.md），避免高频使用以下词汇，但**不是绝对禁用**——偶尔用一次「似乎」「仿佛」是正常的，关键是不要每段都用。每种 AI 词汇的替代方式要在文中混合使用，不要形成新的固定模式
- **叙述推进+对话点睛**：短篇节奏靠叙述推进，对话用在关键情感节点。一句"我去找了他"用叙述1秒就过去，换成对话要写200字。12+个剧情点要在万字内塞完，必须靠叙述快速推进。对话用来展现角色性格、情感碰撞和关键冲突——不是每件事都需要用对话来"演"，日常推进和信息交代用叙述更高效

**反翻译腔**（参考 writing-style.md 第七章，极重要）：
- 名词前修饰语不超过6个字。先写名词，再用独立短句描写属性
- 一个分句不超过2个"的"，严禁"长修饰语+的+名词"结构
- 描写环境/物品时结合动作交互和感官体验，不要罗列静态属性
- 错误：`那扇锈迹斑斑且散发着恶臭的铁门` → 正确：`那扇铁门，锈迹斑斑，散发着一股恶臭`

**节奏**：
- 全文平均每600-800字一个看点（悬念/冲突/反转/信息揭示/情感爆发），但不要均匀——有的段落1000字铺日常，有的段落300字内连续两个看点
- 紧张处用极短句连击，舒缓处用长句或长段落铺开
- 对话占比全文平均 25-35%，**各场景之间波动要大**（有的场景60%对话，有的场景纯叙述0%对话）。短篇用叙述推进剧情，对话用在关键情感碰撞处
- 纯叙述段不超过连续 500 字
- **默认每段不超过30字**（含对话），这是手机阅读的硬指标。但段落长度要有波动：大多数段落1-2句（≤30字），偶尔出现3-4句的中段落，每2000字穿插1-2个4-6句的长段落（用于内心挣扎/回忆/环境铺设），制造节奏变化
- **每个场景至少1次非视觉感官细节**：气味、声音、触感、温度、味道——但用几个字嵌入叙述句中（"药汁苦得我皱脸""风灌进来冷得打哆嗦"），不要写独立的感官描写段落。这是为了反AI检测，不是为了文学性
- **场景内行动闭合**：场景内发出的行动指令（让人去拿东西、派人去做事），**必须有闭合节点**——要么写出执行过程的一个细节，要么写出结果被确认。不能"让阿蛮去拿钥匙"就直接跳到下个场景已经拿到了。差："我让阿蛮去取钥匙。换了身衣裳，去了前厅。"→ 好："我让阿蛮去取钥匙。她小跑着出去，不一会就回来了，钥匙攥在手里。我深呼吸。'更衣，见客！'"

### 输出格式

直接输出完整故事正文。用数字标号分段，不要章节标题。

## Phase 3.5 — 有机改写（不是机械插入，是让文本更像人写的）

全文生成后，**必须执行以下改写操作**。核心原则：**改写必须融入上下文，不能产生接缝感**。每一处修改都要让前后句子自然衔接，读起来像是一气呵成写出来的，不像后加上去的。

### 改写原则

- **流畅度优先于机械达标**：如果某项改写怎么改都会让上下文读起来别扭，就换一个位置改，或者跳过这一处。一篇流畅但少了一句废话的文章，远好过一篇有3句废话但读起来磕绊的文章
- **改写后重读前后3段**：每做一处修改，重读修改处前后各3段，确认行文仍然通顺。如果不通顺，调整直到通顺
- **不要集中改**：改写点要分散在全文各处，不要3处修改都集中在同一个场景里

### 必须执行的改写项

**① 段落节奏调整（1-2处）**
找1-2个日常叙述或内心活动的段落区域，把相邻的2-3个短段落自然合并成1个长段落。合并时重写连接处，让段落内部的句子像是一口气写出来的，不是硬拼的。跳过对话密集段和紧张冲突段。

**② 直接讲述融合（3处）**
找3个用动作展示情绪的地方，把动作展示替换成直接讲述。关键：替换后的句子要和上下文的语气、节奏一致。不是在原文旁边加一句，而是用直接讲述**替代**原来的动作展示。
- 差（接缝感）："她攥紧了袖口。说实话我有点慌。" ← 两种写法并存，明显是后加的
- 好（自然融合）："说实话我有点慌，慌到根本没注意自己攥着袖口攥了多久。"

**③ 废话/跑题有机融入（2-3处）**
在叙述者自然会跑题的地方（等待、发呆、做无聊的事），让叙述者的思维顺势飘到一个无关话题上，然后自然拉回来。废话必须从当前场景的某个感官细节中生长出来，不能凭空出现。
- 差（凭空插入）：剧情推进中突然 → "运气差成这样也是一种天赋。" → 继续推进
- 好（自然生长）：主角在等人，闻到药味 → "这药味跟我姥姥家的中药铺子一模一样，小时候我最怕去那儿，一进门就想吐。" → 门开了，人来了

**④ 结尾改写（最后200字）**
重写结尾最后200字。结尾要求：
- 最后一句必须是一个**具体的身体动作**（走路、关门、喝水、翻身）
- 禁止：感官排比、比喻回调、动物/配角拟人点评、双重强调
- 结尾的语气要和全文一致——如果全文是干脆利落的风格，结尾也干脆；如果全文有余韵，结尾也留余韵

**⑤ 消灭双重强调**
全文搜索「两句不同措辞说同一件事」的地方，删掉一句，保留更有力的那句+角色反应。

**⑥ 信息密度调整（1处）**
找1处连续3+短段落在逐步揭示信息的地方，合并成1个密集的长段落。合并后重写，让信息之间有叙述者的思维跳跃和情绪反应，而不是干巴巴地列事实。

**⑦ 情节桥段堆叠检查**
检查每个场景的经典桥段数量（参见 anti-detection.md 第十二章清单）。超过2个的场景，删掉多余的，并插入一个不浪漫/扫兴的具体细节。

**⑧ 非理性行为检查**
全文是否有至少1个角色做出「不太合理但很真实」的行为？如果没有，找一个合适的角色和场景加入——这个行为要和角色性格有隐约的关联，但不需要在文中解释。

**⑨ 非视觉感官检查**
每个主要场景是否至少有1次非视觉感官描写？缺少的场景，用几个字嵌入已有叙述句中补上，不要加独立的描写句。

**⑩ 结尾动作收束确认**
最终确认：最后一句是具体身体动作。

**⑪ 风格档案保持（仅在选用了风格档案时执行）**
检查以上改写是否破坏了风格档案的签名手法，在不违反反检测规则的前提下恢复。

**⑫ 通读流畅度检查（最后一步，不可跳过）**
改写全部完成后，**从头到尾通读一遍全文**，重点检查：
- 每处改写点前后是否有接缝感（语气突变、节奏断裂、信息不衔接）
- 全文整体读起来是否像一个人一气呵成写的，还是像拼接出来的
- 如果发现任何不自然的地方，当场修复

改写完毕后进入 Phase 3.8。

## Phase 3.8 — 质量自检

读取 `references/quality-checklist.md`，对全文执行以下检查（重点检查高风险项）：

### A. 过稿必检项（直接对应编辑拒稿标准，未通过则必须修改）

1. **套路化检查**：逐场景检查——这个场景的冲突模式在前面是否出现过？如果两个场景的冲突可以概括为同一句话（如都是"被冤枉→自证清白"），必须改掉其中一个的冲突结构
2. **张力曲线检查**：全文的冲突赌注是否总体上升？标记每个场景的赌注等级（低/中/高/极高），如果出现赌注下降后没有回升的情况，调整场景顺序或加码赌注
3. **流畅度抽检**：随机抽3个段落朗读，是否有拗口、别扭、不自然的句子？特别注意 Phase 3.5 改写过的位置是否产生了接缝感

### B. 质量基础项

4. **伏笔回收**：全文埋的伏笔是否全部回收？有没有「提了但没收」的悬案？
5. **时间线**：人物年龄和事件间隔是否自洽？如果涉及「X年前」「等了X年」这类表述，交叉验证数字
6. **逻辑红线**：每个重要转折前是否有铺垫？角色动机是否被看见？有没有凭空出现的巧合？
7. **物理连续性**（参见 quality-checklist.md）：物品流转是否完整（让人去拿的东西拿回来了吗）？角色位移是否连贯（派出去的人回来了吗）？动作序列是否物理可行？**这是最容易出硬伤的地方**
8. **主角底线**：主角是否有明确不可退让的东西？是否有爆发点？
9. **获得感**：读者读完后心里能「多点什么」吗？至少满足：1处情感共鸣 + 1处情绪释放 + 3句可截图金句（三种中满足两种即可）
10. **内部查重**：同类场景有没有重复出现但没有新信息？同一情绪有没有原地打转没有递进？
11. **细节创新**：全文是否有至少1处「读者没见过的具体动作或细节」——在大家以为「到这里就该这样了」的位置，做了一个意外的事？

如果发现问题，直接修改。修改完毕后输出最终版本，不要展示修改过程。

## Phase 4 — 发布素材 + 导出

故事生成完毕后，立即生成发布素材并与正文合并保存。

### 发布素材格式

```markdown
# 发布素材

## 导语

150-220字，一句一段，放在正文最前面。包含：核心冲突暗示 + 人物底色展示 + 情绪钩子 + 信息缺口。结尾必须有未解决的悬念。

## 书名建议
每个书名严格控制在15字以内（含标点），超过15字必须缩短。
1. **书名1** — 为什么好
2. **书名2** — 为什么好
3. **书名3** — 为什么好

## 主角人设
- 女主：姓名 — 人设标签
- 男主：姓名 — 人设标签
- CP线：一句话对比句

## 标签
标签1、标签2、...（8-10个）

## 金句 / Hook
1. "金句1" — 适用场景
2. "金句2" — 适用场景
3. "金句3" — 适用场景

## 一句话简介
50字以内

## 作品简介（100字）
...

## 详细简介（300字）
...
```

### 保存文件

将「发布素材 + 正文」合并为一个 markdown 文件，保存到用户桌面。
文件名用书名建议的第一个（已限制15字以内，可直接作文件名）。路径：

- Windows (WSL): `/mnt/c/Users/*/Desktop/`
- macOS: `~/Desktop/`

保存前问用户确认文件名和路径。

---

## 重要原则

- 不要在生成过程中解释你在做什么，直接输出内容
- 概念头脑风暴时输出要紧凑，不要写太多解释
- 全文生成时不要分段输出让用户确认，一气呵成
- 生成的故事是独立的完整作品，不依赖任何外部系统
- **内容安全**：不要挑战知乎审核底线。避免涉及政治敏感、色情暴力擦边、侮辱性内容。安审被卡可能导致整篇被毙，几万字白写。如果剧情需要涉及灰色地带（黑道、犯罪等），用曲线表达，不要说得太明显
